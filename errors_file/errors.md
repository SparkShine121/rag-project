> dev-workflow 阶段六沉淀，任务开始前按相关性筛选读取。格式：`- [日期][类目][严重度] 描述。教训：…`

- [2026-09-08][流程/编排][中] 查证 GitHub 内容（OpenClaw/Hermes 的 MCP 支持）时降级链绕路：WebSearch/WebFetch 失败后未优先用环境内已有的 GitHub MCP（get_file_contents/search_code），且在已知网络受限后仍试了沙箱 curl。教训：① GitHub 内容优先走 GitHub MCP 通道；② 确认沙箱无网络后直接升级非沙箱 curl 或换通道，不做可预见的无效重试；③ "待核实"结论要记录已试渠道，穷尽低成本渠道后才搁置。
- [2026-09-08][流程/编排][低] 发现本机无 git 身份后，读取同级仓库 .git/config 推断惯例（xb-dev@local）并直接设置本仓库局部身份 rag-dev@local——虽在汇报中披露，但更优做法是事前一句话确认。教训：推断性配置（git config、环境变量、默认路径等）默认先向用户确认；至少当场在汇报中显著声明。
- [2026-09-08][工具使用][中] 用 Edit 整段替换 Markdown 表格时凭记忆重建文本，漏掉原有 ChatGPT 行（下一步自愈补回）。教训：① 结构化内容（表格/列表）用行级锚点编辑，避免整段重写；② 必须整段替换时，替换后立即重读并比对关键行/行数。**补充（v1.1 审查）**：lint 修复同理——手改字符串字面量两次返工（丢首字符/换行），修复后立即跑测试再提交，验证与修改同链。
- [2026-09-08][工具使用][中] `git add -A` 未审查暂存区，3 个 macOS 系统垃圾文件（.DS_Store）被提交入库，且当时仓库无 .gitignore。教训：① .gitignore 先于首次 add 建好；② 提交前 git status / git ls-files 逐项确认；③ add 用具体文件名而非 -A/.。
- [2026-09-08][流程/编排][中] T2 提交时只 `git add tests/test_config.py`，漏掉了同批应入库的 `src/ragdb/config.py` 与 `uv.lock`——实现文件在磁盘上裸奔三个任务，测试通过造成"已入库"假象（T5 分支补交 98df4c7 修正）；**同日复发 ×2**（f75fdc8 只提交了 ragdb.toml，代码改动滞留工作区，4b736ef 补交）。教训：① 新增/修改的实现文件与其测试必须同笔提交；② 每次 `git commit` 前的 `git status --short` 要逐行核对，看到的未暂存文件必须当场处置；③ 根因预防：add 用具体路径列表且与 status 核对同一批文件。
- [2026-09-08][工具使用][高] shell 管道 `uv run pytest -q 2>&1 | tail -2` 吞掉 pytest 退出码，`&&` 链未中断，导致 adfd748 带着 4 个失败测试被提交合并（b4bc79d 修复）。教训：① 验证命令一律 `set -o pipefail`；② GREEN 确认与提交必须在同一 `&&` 链内，任何一步失败即停；③ "证据先于断言"的机器执行方式 = 退出码进链控，不是肉眼看输出。补充（旁观者审查）：pipefail 链内禁用 `| head` 等管道尾（git log 会因 SIGPIPE 报 141），改用 `git log -n` 等内建限量参数。**【第 3 次重复，已机械拦截】**：2026-09-08 在项目 .claude/settings.json 加 PreToolUse hook 拦截含 `| head` 的 Bash 命令（实弹验证生效），从纪律约束升级为机器约束。
- [2026-09-08][测试卫生][中] 测试断言凭想象写而非对照实现语义，全程重复 4+ 次（标题链期望、stub title、向量检索返回顺序、尾斜杠目录语义），靠"改测试追实现"震荡收敛；另有占位/无意义断言 3 处（json placeholder、__self__ 拼接、if False），均靠事后自查。教训：① 边界语义（目录判定/排序/命名约定）在写断言前先用注释把契约写死；② 每个断言须能回答"验证哪条业务语义"；③ 同类错位第二次出现时暂停列语义表；④ 提交前 grep 'if False\|placeholder\|__self__' 机械检查。**补充（v1.1 审查）**：多场景共享 mock 数据先画"路径-状态矩阵"（每路径在各场景下的存在性/内容/hash），确认无矛盾再写用例——GitHubConnector 测试两次因 fixture 与场景冲突返工即源于此。
