# ragdb 智能体接入与操作指南

> 面向要接入 ragdb 的智能体（Claude / OpenClaw / Hermes / 任意可调 HTTP 的 agent）及其配置者。
> 版本基线：v0.1.0（2026-09-08）。本文与实现同步维护，发现不一致以代码为准并反馈。

---

## 1. ragdb 是什么

本地个人 RAG 检索服务：把 Obsidian 知识库（vault）向量化，提供**语义检索 + 整篇笔记读取 + 清单浏览**三类只读能力。

- **模型**：BAAI bge-m3（嵌入，1024 维）+ bge-reranker-v2-m3（重排），跑在本机 Apple GPU（MPS）
- **三种接入通道**（任选，能力完全相同）：

| 通道 | 适用场景 | 地址/命令 |
|---|---|---|
| stdio MCP | 同机 agent：Claude Code/Desktop、Hermes、OpenClaw | `uv run ragdb-mcp`（需指定项目 cwd） |
| Streamable HTTP MCP | 远程 agent、不便配 stdio 的客户端 | `http://127.0.0.1:8770/mcp` |
| REST API | 任何能发 HTTP 的程序（无 MCP 能力也行） | `http://127.0.0.1:8770/api/v1/*` |

- **硬约束（重要）**：
  1. **全链路只读**——ragdb 绝不写入/修改/删除知识库笔记，MCP 无任何写工具；
  2. 仅监听 `127.0.0.1`，不暴露公网；
  3. 单写者——只有 serve 进程能写索引库（`ragdb.lock` 保护），所有消费端只读。

## 2. 前置条件（配置者做一次即可）

```bash
cd <ragdb 项目根目录>
uv sync --extra dev            # 安装依赖（uv 自动准备 Python 3.12）
uv run ragdb sync              # 首次建索引（模型首次下载约 4.5GB，走 hf-mirror，约 5-20 分钟）
```

- 配置文件 `ragdb.toml`（每个参数带语义注释）；环境变量 `RAGDB_*` 可覆盖（如 `RAGDB_PORT`）。
- 模型下载需网络，国内环境先 `export HF_ENDPOINT=https://hf-mirror.com`；之后离线可用（`HF_HUB_OFFLINE=1`）。
- **模型本地缓存位置（已下载，勿重复下载）**：两个模型已缓存在 HuggingFace 默认缓存目录，启动时库会自动复用，无需联网重新下载：

  | 模型 | 缓存路径 | 大小 |
  |---|---|---|
  | BAAI/bge-m3（嵌入，1024 维） | `~/.cache/huggingface/hub/models--BAAI--bge-m3` | 约 4.3 GB |
  | BAAI/bge-reranker-v2-m3（重排） | `~/.cache/huggingface/hub/models--BAAI--bge-reranker-v2-m3` | 约 2.1 GB |

  - 判断是否已缓存：`ls ~/.cache/huggingface/hub/ | grep BAAI`。
  - **清理缓存目录时务必避开 `models--BAAI--*`**，误删会导致下次检索触发约 6.4 GB 的重复下载。
  - 缓存目录可通过 `HF_HOME` / `HF_HUB_CACHE` 环境变量改址；改址后需重新下载或迁移旧缓存。
- 常驻服务（推荐后台常开，agent 随时可用）：

```bash
uv run ragdb serve   # REST :8770 + /mcp + 每 30s 自动同步 vault 变更
```

## 3. 通道一：stdio MCP（推荐给同机 agent）

### 3.1 Claude Code / Claude Desktop

`mcpServers` 配置（`claude.json` / Desktop 设置）：

```json
{
  "mcpServers": {
    "ragdb": {
      "command": "uv",
      "args": ["run", "ragdb-mcp"],
      "cwd": "<ragdb 项目根目录的绝对路径>"
    }
  }
}
```

> **`cwd` 必填**：ragdb 从工作目录发现 `ragdb.toml`；不设 cwd 会读不到配置。

### 3.2 Hermes Agent / Hermes Agent CN Desktop

`~/.hermes/config.yaml`——推荐用仓库自带的 `ragdb-mcp-launcher.sh` 启动器（自动固定 cwd、启用 HF 离线模式、直连 venv，不依赖 uv/PATH）：

```yaml
mcp_servers:
  ragdb:
    command: "<ragdb 项目根目录的绝对路径>/ragdb-mcp-launcher.sh"
```

也可用标准方式（`command: "uv"` + `args: ["run", "ragdb-mcp"]` + `cwd`）或 `hermes import-agent claude-code` 直接迁移 Claude 的配置。远程部署的 Hermes 用通道二。

### 3.3 OpenClaw

```bash
openclaw mcp add ragdb --command uv --arg run --arg ragdb-mcp
openclaw mcp doctor ragdb --probe   # 验证连通
```

## 4. 通道二：Streamable HTTP MCP

- 端点：`http://127.0.0.1:8770/mcp`（serve 运行时可用）
- 传输：MCP Streamable HTTP；连接前先发 `initialize` 握手，服务端返回 `mcp-session-id` 响应头，后续请求携带该头。
- **注意**：服务端启用 DNS rebinding 防护，请求的 `Host` 头必须是 `127.0.0.1` / `localhost`（用 IP 直连，勿用自定义域名指向 localhost）。
- 适合：跑在其它机器但能访问本机网络的 agent（公网暴露属 v2，需自行加隧道+鉴权）。

## 5. 通道三：REST API

基址 `http://127.0.0.1:8770`。所有错误统一为：

```json
{ "error": { "code": "validation_error | not_found | internal_error", "message": "…" } }
```

### 5.1 POST /api/v1/search —— 语义检索

请求体：

```json
{ "query": "RAG 项目的分块与聚合方案", "top_k": 5, "folder": null, "tags": null }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `query` | ✅ | 检索词；空白串返回 422 |
| `top_k` | 可选 | 返回条数上限（1-50，默认取配置 `top_k`=5） |
| `folder` | 可选 | 目录过滤，语义见 §7.1 |
| `tags` | 可选 | 标签过滤，**交集**匹配（笔记须含全部给定标签） |

响应（数组，按相关度降序）：

```json
[
  {
    "source_id": "obsidian/自己的项目/RAG项目/技术栈方案.md",
    "title": "技术栈方案",
    "heading_path": "技术栈方案 > 一、分块与聚合方案 > 1.3 为什么这么做",
    "snippets": ["…命中块及相邻块拼合的正文…"],
    "whole_note": false,
    "score_rerank": 0.947,
    "score_dense": 0.83,
    "tags": ["RAG项目", "技术选型"]
  }
]
```

curl 示例：

```bash
curl -s -X POST http://127.0.0.1:8770/api/v1/search \
  -H "Content-Type: application/json" \
  -d '{"query":"分块与聚合方案","top_k":2}'
```

### 5.2 GET /api/v1/notes —— 清单

```
GET /api/v1/notes?folder=obsidian/自己的项目/&tag=RAG项目
```

响应：`[{"source_id": "…", "title": "…", "tags": ["…"]}]`（按 source_id 升序，不含正文）。

### 5.3 GET /api/v1/notes/{source_id:path} —— 整篇笔记

```
GET /api/v1/notes/obsidian/自己的项目/RAG项目/技术栈方案.md
```

响应：`{"source_id", "title", "tags", "content"}`；不存在返回 404。`source_id` 为来源前缀 + 来源内路径（见 §7.2）。

### 5.4 POST /api/v1/sync —— 触发增量同步

请求体 `{"full": false}`（`true` = 全量重建）。响应：

```json
{ "added": 0, "updated": 0, "deleted": 0, "moved": 0, "failed": [], "duration": 0.0034 }
```

`failed` 元素为 `[source_id, 原因]`。一般不需要手动调——serve 每 30s 自动同步。

### 5.5 GET /api/v1/health —— 健康检查

```json
{ "status": "ok", "db_ok": true, "models_loaded": true, "note_count": 27, "last_sync_at": "…" }
```

`models_loaded=false` 仅表示当前进程尚未用到模型（懒加载），不代表故障。

## 6. MCP 工具（stdio 与 /mcp 同一套，共 3 个只读工具）

### 6.1 `search(query, top_k=5, folder=None, tags=None) -> str`

语义检索。返回人类/模型可读文本：

```
## 自己的项目/RAG项目/技术栈方案.md（技术栈方案）[片段]
标题链: 技术栈方案 > 一、分块与聚合方案 > 1.3 为什么这么做
相关度: 0.947
<命中及扩展的正文片段>

## <下一条…>
```

`[整篇]` 表示该笔记较短、直接返回了全文；`[片段]` 表示返回命中块±1 相邻块拼合。无结果时返回"未找到相关内容。"；空查询返回提示文本。

### 6.2 `get_note(source_id) -> str`

按路径读整篇：`# 标题\ntags: …\n\n正文`。不存在返回"未找到笔记: {source_id}"（不抛异常）。

### 6.3 `list_notes(folder=None, tag=None) -> str`

每行一条：`{source_id} | {title} | tags: {…}`；空返回"（空）"。

**调用建议（给 agent 的启发式）**：
- 先 `search` 拿到 source_id 与相关度，需要全文再 `get_note`，避免整篇塞上下文；
- 用 `folder` 缩小范围（如只想查某个项目目录）；
- `search` 结果里 `heading_path` 可当作笔记内目录，帮助你判断是否值得读全文。

## 7. 行为细则（避免踩坑）

### 7.1 folder 过滤的目录边界语义

| 传入值 | 匹配范围 |
|---|---|
| `"我的项目/"`（带尾斜杠） | 仅 `我的项目/` 下的笔记 |
| `"我的项目"`（无尾斜杠） | `我的项目/` 下笔记 **+ 同名文件** `我的项目.md` |
| 两种写法 | **都不匹配**兄弟目录 `我的项目2/` |

### 7.2 多来源与路径前缀（v1.1）

- 检索结果/笔记路径的 `source_id` 带**来源前缀**：`obsidian/自己的项目/技术栈方案.md`、`myrepo/README.md`（前缀 = 配置里的来源名）。
- `folder` 过滤天然跨源：`folder="myrepo/"` 只查该 GitHub 仓库；`folder="obsidian/自己的项目/"` 只查 vault 某目录。
- 来源在 `ragdb.toml` 的 `[[sources]]` 中增删改，**首次同步自动清理被移除来源的孤儿索引**，无需手动 rebuild。
- 当前支持的来源类型（v1.2）：`obsidian`（本地 md 目录，恒 md-only）、`folder`（本地任意目录，按白名单收 md/代码/PDF）、`github`（仓库，按白名单）。
- PDF 按页切块（标题链含页码，如 `报告.pdf > 第 3 页`）；无文本层的扫描版 PDF 自动走 Apple Vision OCR 回退（本机推理），识别失败进 failed 报告。
- 过滤配置在 `ragdb.toml` 的 `[ingest]`：扩展名白名单、单文件上限（默认 50MB）、来源文件数上限（默认 5000）、排除目录；来源可用同名字段覆盖。

### 7.3 索引时效

- serve 运行中：vault 变更 ≤30s 自动入索引（`interval_secs` 可调，0 = 关闭自动同步）。
- 未起 serve：改动后需手动 `uv run ragdb sync`。
- 笔记清空正文 → 旧向量会被清除；重命名/移动 → 只更新元数据不重嵌入（秒级）。

### 7.4 写入权与锁

- 只有 serve 进程持有 `ragdb.lock`；CLI `sync` 检测到 serve 存活会自动转调其 HTTP（不会抢锁）；serve 不在时 CLI 才自己写。
- 第二个 serve 实例启动会直接报错"ragdb.lock 已被占用"——这是预期行为，不是故障。

### 7.5 错误速查

| 现象 | 原因与处置 |
|---|---|
| search 返回全空但笔记存在 | 索引未建/未更新：跑 `uv run ragdb sync`；或 serve 未运行而你在查旧数据 |
| HTTP `/mcp` 返回 421 | 请求 Host 不是 127.0.0.1/localhost（DNS rebinding 防护），改用本地地址访问 |
| 第二个 serve 起不来 | 写锁被占：先停旧 serve |
| 首次检索很慢 | 模型冷加载 ~15s（每进程一次），常驻 serve 后无此开销 |
| `ragdb-mcp` 报找不到配置 | 未设 cwd，或 `ragdb.toml` 不在工作目录 |

## 8. 能力边界（v1）

- 只读：无任何写入/修改/删除笔记的工具（写能力规划在 v2）；
- 仅支持 vault 内 Markdown 笔记（图片/PDF、微信读书、聊天记录等新渠道在 v2 路线图）；
- 不暴露公网（远程接入需自建隧道+鉴权后走通道二）；
- 检索延迟基线（M4 实测）：热查询 0.7-1.2s（`rerank_top_k=5`），模型冷加载 ~15s/进程。
- **内存行为**：serve 空闲（未加载模型）约 250MB；首次检索后模型驻留约 4-5GB；`unload_idle_secs`（默认 1800）秒无检索自动卸载回落至 ~1.4GB，下次检索自动重载并伴随一次冷加载延迟。
